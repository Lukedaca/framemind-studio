# FrameMind Studio 0.1.6

25 October 2026 · Windows x64 · unsigned development preview

Previous versions restored the last working photo set at startup and appended
new imports to it, but offered no general action to clear the set. This patch
adds **Clear photo set / Vyprázdnit sadu** below the workflow in the left sidebar.

## Clearing the working set

- Available from import, culling and the editor, with confirmation. Cancelling
  preserves the photos and their history.
- Confirmation clears the working set and its complete Undo/Redo history,
  detaches the open project and returns to an empty import screen. Export work
  outside a saved project before clearing it.
- Saved projects, clients and original disk files are kept. Reopening a saved
  project deliberately opens that project's photos again.
- One IndexedDB transaction saves the empty set and deletes image records no
  saved project or any of its past/present/future history entries needs.
  Startup, ordinary saves and installation do not trigger this cleanup.
- An import already in progress cannot add its photos back after clearing or
  switching projects. Clear remains available when only Undo/Redo history remains.
- Save errors and Retry remain visible outside the editor. Wait for Saved locally
  before closing. If a clear fails, the previous persisted state and image records
  remain intact and can return after restart until a retry succeeds.

## Verification

Checks completed locally on 25 October 2026:

- TypeScript and 208 tests across 27 files passed. The final test run used
  `node node_modules/vitest/vitest.mjs run --maxWorkers=2`.
- The desktop frontend, Rust application and Windows NSIS installer built successfully.
- The existing browser history/persistence check passed, including save failure,
  retry, project isolation and complete browser shutdown/restart.
- The new browser clear check passed cancellation, delayed imports, atomic
  rollback after cleanup was aborted, Retry, preservation of saved projects and
  their history image assets, a fresh import, a Redo-only set and a browser restart.
- The same clear check passed in the installed 0.1.6 WebView2 application with
  synthetic photos and a separate profile. A separate complete process restart
  preserved the empty set, saved project and its three referenced image assets.
  Original test-file hashes were unchanged and page errors were zero.
- All 346 files in the normal IndexedDB/localStorage workspace matched their
  pre-check SHA-256 hashes during the update and tests, before reopening the normal app.

The installed executable was tested directly rather than assuming it had the
same hash as the unbundled executable. Tauri changes its bundle-type marker when packaging NSIS.
The installed executable that passed native checks had SHA-256
`16af65de3558ee00abb40d189d58a1463a2da21aa427979a3fa5bd5a49b306cd`.

Native export, model inference and general photographic accuracy were not retested
for this patch. Culling remains `local-1.6`; retouch response and model reuse remain
as described in [0.1.5](0.1.5.md). Earlier features and evidence limits are in
[0.1.4](0.1.4.md). These synthetic checks do not validate every existing project
or every Windows/GPU configuration.

## Download and limits

Download the installer and `SHA256SUMS.txt` from
[GitHub v0.1.6](https://github.com/Lukedaca/framemind-studio/releases/tag/v0.1.6).
The approximately 220 MiB Windows x64 installer remains unsigned and is a
development preview. A signed client release and installation on clean Windows
without an existing WebView2 runtime remain unverified. Do not disable Windows protection.

The entire Studio is not fully offline: model/font downloads and optional Gemini
editor functions retain their documented behavior. GitHub hosts source code and
downloads; no Studio hosting deployment is part of this release. Installation
keeps local data; clearing the working set requires the explicit action above.
